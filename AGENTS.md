# Reacting AI Project Instructions

Before making any design, UX, UI, branding, copywriting, website or product decisions, always read the following documentation first.

## Documentation

1. /docs/Reacting-Design-Bible.md
2. /docs/REACTING WEBSITE PLAYBOOK.md

These documents are the source of truth.

Never contradict them.

Never invent a different design language.

Never invent a different marketing message.

Never redesign pages based only on preference.

Always explain if a requested change conflicts with the Design Bible or Website Playbook.

When documentation does not yet exist for a page or feature, ask before inventing a solution.

When implementing changes:
- Follow the Reacting Design Bible.
- Follow the Website Playbook.
- Reuse existing components whenever possible.
- Do not create duplicate design patterns.
- Think like a Senior Product Designer, UX Designer and Software Architect, not only a developer.
# Before every implementation

Before writing code or suggesting changes, always ask yourself:

1. Does this reduce operational friction?
2. Does this reduce another conversation?
3. Does this reduce another spreadsheet?
4. Does this reduce another manual process?
5. Does this create better visibility?
6. Does this strengthen the position of Reacting as the Operational Platform for Modern Dental Practices?
7. Is this the simplest solution?
8. Will this still make sense in ten years?

If the answer to most of these questions is "No", redesign your proposal before presenting it.
